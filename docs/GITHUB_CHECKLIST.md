# Checklist GitHub para la rúbrica

El archivo ZIP no puede demostrar por sí solo el indicador de trabajo colaborativo en un repositorio remoto. Antes de entregar:

1. Sube esta carpeta al repositorio público del equipo.
2. Evita subir todos los cambios en un solo commit. Usa mensajes breves y descriptivos.
3. Distribuye commits entre los integrantes según el trabajo realizado.
4. Verifica que el historial muestre integración real del equipo.

## Ejemplos de mensajes de commit

- `feat: estructura semantica y navegacion de la tienda`
- `style: diseño responsivo de catalogo y formularios`
- `feat: productos dinamicos y carrito con localStorage`
- `feat: validaciones de registro login y contacto`
- `feat: mantenedor administrativo de productos`
- `feat: mantenedor de usuarios y roles`
- `fix: validacion de RUN y stock critico`
- `docs: agrega ERS v1 y credenciales de demostracion`

No inventes commits a nombre de compañeros: cada integrante debe realizar y explicar sus propios cambios.
